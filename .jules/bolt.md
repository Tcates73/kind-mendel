# Bolt's Journal

## 2025-07-18 - R3F Off-React-Thread Rendering Pattern
**Learning:** In React-Three-Fiber (R3F), when 3D object positions are updated continuously by a physics engine or tickers, rendering performance degrades if we trigger standard React component re-renders for every single update. Because the position updates are handled imperatively inside the `useFrame` hook (e.g. by mutating `groupRef.current.position.lerp()`), the component's JSX structure, material bindings, and React Fiber nodes do not need to re-render. Standard `React.memo` fails here because parent renders re-create new position array instances on every frame.
**Action:** Always wrap R3F elements (like `ImageCard`) in `React.memo` with a custom comparator that does deep numeric comparison of coordinates (`prevProps.position[0] === nextProps.position[0]` etc.) and bypasses inline callbacks. This shields the React render tree from frequent physical simulation updates while still keeping the `useFrame` animation fully functional.

## 2025-07-20 - React-Compliant Simulation Stability Pattern
**Learning:** In React, mutating arrays in-place (e.g. `arr[0] = x`) inside state objects breaks React's shallow reference comparison contract. Even if child components use `useFrame`, bypassing React's standard reactivity can lead to frozen UI frames, stale props, or failed updates if other components rely on standard hook dependency arrays.
**Action:** Instead of mutating arrays in-place, compute the difference between previous and current positions. If the change is below a microscopic threshold (e.g., `1e-4`), reuse the previous array reference (`newPositions[id] = prev`). If it is above, allocate a new array. Only trigger state updates when at least one node has shifted. This keeps the application 100% React-compliant, allows `React.memo` to perfectly bail out of rendering stable nodes, and completely stops React rendering when the physics simulation settles.

## 2025-07-24 - Single-Tick Physics Key Synchronization Pattern
**Learning:** In continuous physics-based graph simulations (like d3-force-3d inside React hooks), syncing simulation positions to React state on every 'tick' requires validating that deleted nodes are properly removed from the previous state. Calling `Object.keys(currentPositions)` and searching for mismatches on every frame creates heavy garbage collection overhead (creating arrays of string keys 100+ times per second). However, the set of active nodes in the simulation is constant for the entire lifespan of a single `useEffect` execution. Key mismatches can *only* occur on the very first tick of a restarted simulation.
**Action:** Track whether it is the first tick using a simple boolean flag inside the simulation creation closure. On the first tick, use an allocation-free loop (e.g., `for...in`) to count the previous keys, compare, and then set the flag to false. On all subsequent ticks, completely bypass key counting and missing-key checks as they are guaranteed to match.

## 2025-07-26 - Boolean State Lifting vs ID Callbacks Pattern
**Learning:** Passing a parent state string (like `hoveredId`) down to every child node in a mapped array causes every child to re-render on *any* hover transition because the `hoveredId` prop changes for all of them. Additionally, creating inline closures in render maps like `(pos) => onDrag(id, pos)` recreates callback references on every frame, which completely breaks `React.memo` optimization and forces full component renders.
**Action:** Compute contextual boolean state transitions (like `isOtherHovered`) in the parent mapping loop and pass only the boolean value to the children. Elevate the child identifier (`id`) into the callback signature itself (e.g., `onDrag(id, pos)`) to pass reference-stable callback handlers directly, enabling `React.memo` to perfectly bail out of rendering unaffected sibling items.
